# Adaptive Facial Protocols V3.3

## Approval model

`approved: true` means the modality has an approved general-facial execution path under Dr. Aakriti's constraints.

It does not mean that every client receives a fixed preset.

```text
optimizer selects modality and zones
→ AI selects client-specific settings
→ explicit constraints are validated
→ valid protocol compiles automatically
```

## Validation philosophy

Validate only the settings that have explicit clinical/device constraints.

Do not block simple facial steps because they lack a stored preset.

## Q-Switch

```text
wavelength: 1064 nm
energy: 100–2000 mJ
frequency: 1–10 Hz
spot area: 1 cm²
passes: 1–2
```

Every zone-specific value must remain within these limits.

## Carbon Facial

Carbon Facial uses the same 1064-nm laser capability envelope and the 1–2-pass limit. The optimizer may select it only when direct oil, congestion, pore or appropriate acne utility is material.

## Simple autorelease steps

The following categories do not require machine-parameter validation:

- Hydrafacial probes and modular components;
- LED;
- microdermabrasion/exfoliation;
- infusion;
- extraction;
- masks;
- lymphatic drainage;
- final serum, moisturiser and sunscreen.

The AI may choose duration, product/solution and zones.

## Chemical peels

Fixed neutralisation constraint:

```text
contains glycolic or lactic acid
→ alkaline neutraliser

all other facial peels
→ normal saline (NS)
```

Contact time, layers and endpoint remain adaptive clinical fields.

## Safety

Automatic release still requires:

- eligibility not denied;
- regional temperatures below the denial threshold;
- valid selected zones;
- all explicit machine constraints satisfied;
- required protection and stop conditions retained.

No live treatment-approval prompt is created.
